# 패키지 책임 계약

## 현재 상태와 확정 책임

현재 Flutter package 기반만 있다. 다음은 구현 완료 목록이 아니라 개발할 책임의 경계다.
공개 위젯·형상 타입·표시 입력·글꼴 API·선택/정렬 명령은 아직 없다.

| 책임 | 소유 범위 |
|---|---|
| r_edit_viewer | 도형·글자 화면 표시, 도면↔화면 변환, 확대/이동, 선택 표시, 기준점/경계 보조선 |
| 앱 | 사용자 명령·열린 작업 수명·플랫폼 자원 접근과 패키지 연결 |
| workflow/업무 측 | 제품/발주/작업 규칙·참조/변경 정합성. viewer가 업무 세션을 소유하지 않음 |
| 배치 엔진 | 자동 줄바꿈·후보 탐색·배치 계산. viewer 표시 성공이 배치/제작 성공이 아님 |
| 외부 형식 경계 | DXF 해석/생성·원래 STYLE/삽입점 의미를 표시용 내용으로 변환 |
| 공통 글꼴 외곽 측정 책임 | 실제 자원·glyph 배치·외곽 근거. 향후 엔진에서도 사용할 수 있어야 하며 viewer 의존성을 강제하지 않음 |

마지막 책임의 패키지 위치·기술·소유 API는 미정이다. 별도 저장소/패키지·추측성 인터페이스는 만들지 않는다.
viewer 입력은 계산 결과와 외부 파일에서 얻은 도안을 모두 표현하는 방향이며 DXF 엔티티 구조를 내부 정본으로 확정하지 않는다.
현재 workflow 의존성은 없고 그 기하 타입을 복제하지 않는다. 공유 타입/연결/단위 전달은 다음 계약에서 결정한다.

## 글자 표시의 확정 설계 원칙

- TypeEdit처럼 **실제 글자 외곽**을 선택 경계와 객체 정렬의 근거로 사용해야 한다.
  advance는 공백을 포함한 진행량, baseline은 배치 기준선, ink outline/bounds는 실제 외곽이다. 서로 대체하지 않는다.
- 그리는 글자와 외곽 측정은 동일한 실제 font/face·glyph 선택/배치·변환 근거를 사용해야 한다.
  한쪽은 대체 글꼴, 다른 쪽은 요청 글꼴 또는 별도 문자별 추산을 사용하는 구조는 허용하지 않는다.
- 공통 측정 결과는 화면 확대와 독립된 도면 좌표/단위의 근거다. 확대·이동·DPI는 화면 변환이며 측정값을 다시 만들지 않는다.
- 같은 크기/글꼴 조건에서 H/x/g/한글의 외곽 높이가 달라도 문자열마다 em 배율을 자동 재설정하지 않는다.
  명목 크기·em·cap/행 메트릭·실제 외곽 높이의 의미를 구분한다. 과거 HY 보정값을 공통 상수로 채택하지 않는다.
- 원문과 반복/앞뒤 공백을 그대로 보존한다. 공백에 잉크가 없을 수 있는 것과 진행량이 없는 것은 다르다.
  외곽 없음의 표현·전체 공백 선택 정책은 후속 계약에서 결정하며 임의 사각형으로 채우지 않는다.
- DXF 원래 삽입점/정렬점 해석은 외부 형식의 기준이다. 외곽 왼쪽/중심 등을 맞추는 사용자 정렬 명령은 별도다.
  기존 삽입점을 조용히 외곽 min으로 바꾸지 않는다. 정렬 명령 반영의 소유권은 앱/편집 계약에서 정하고 viewer의 선택 보조와 구분한다.
- 글꼴 없음·glyph 없음·fallback·측정 미지원/불일치를 정상 외곽·기본 font·폭 0으로 감추지 않는다.
  필요한 실제 자원/근거가 없으면 표시/외곽의 확인 수준과 미지원 원인을 구분해야 한다.

외곽 추출·측정은 엔진에서도 재사용해야 한다. Flutter 위젯/viewport에서만 얻을 수 있는 값을 공통 근거의 필수 정본으로 삼지 않는다.
동일 근거를 전달하는 방식·윤곽/배치 자료 수명·원문 위치 단위·회전/자폭의 적용 순서와 정렬 대상 범위는 후속 설계 대상이다.

## 범위 밖과 미정

이번에는 렌더러·DXF 실험 이전·글꼴 도구 선정·배치/제작 판정·저장·동기화·앱 연결을 구현하지 않는다.
공유 geometry/글꼴 데이터 타입, 외곽의 정확성/곡선 근사/허용 오차·선택 hit-test 정책·입력 수명·오류 API는 미정이다.
native backend 필요성은 실물 지원/성능/배포/라이선스 검토 뒤 판단한다. 현재 Flutter plugin이 아니다.
`example/`은 후속 독립 실행/검증 화면의 위치이며 지금은 만들지 않는다.
