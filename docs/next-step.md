# 다음 작업

현재는 독립 Flutter package 개발 기반만 구현되어 있다. 표시 API/공유 타입·공통 측정 backend는 없다.
[글자 표시와 공통 글꼴 외곽 측정 연결 계약](text-outline-binding.md)을 문서로 설계했다.
공통 처리에서 확정한 glyph 배치/외곽을 viewer가 표시하는 방식을 추천했으며,
기존 DXF 실험의 advance 정렬·논리 상자·HY cap 값을 새로운 외곽 정렬 규약으로 채택하지 않았다.

다음 한 가지는 **계약 검토 후 동일 glyph 배치/윤곽의 끝까지 전달을 검증하는 최소 실험**이다.
가장 큰 위험인 동일 face/glyph의 배치·곡선 측정과 실제 표시의 일치, 제어점 경계와 실제 극점,
자폭/회전·화면 확대의 좌표 분리, 공백의 외곽 없음·실패 구분·자원 수명을 함께 확인한다.
실험의 구체 범위/성공 조건은 연결 계약 12절을 따른다. 현재 새 example/패키지/표시 인터페이스는 만들지 않았다.

기존 DXF → CAD/TypeEdit 검증 경로의 재시험은 선행 조건이 아니다.
이번 문서 작업에서 운영 코드·테스트·의존성·SDK·형제 프로젝트·스테이징은 변경하지 않았다.
문서 경로/용어·변환/곡선 예시를 검사하며 Dart/Flutter 전체 검증·실기 시험은 반복하지 않는다.
